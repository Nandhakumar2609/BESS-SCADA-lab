# IEC 62443 mapping

This lab is **inspired by** IEC 62443 (it is not a certified system). The target is roughly
**SL 2** ("protect against intentional violation using simple means, low resources, generic skills")
for the control and DMZ zones.

## Zones and conduits (IEC 62443-3-2)

| Zone | Assets | SL-T | Why |
|---|---|---|---|
| Z1 Field (VLAN 10) | PCS, BMS, HVAC, meters | 2 | Safety-relevant equipment; Modbus has no authentication, so protection comes from the zone boundary |
| Z2 Control (VLAN 20) | SCADA gateway / site controller | 2 | Only component allowed to command Z1 |
| Z3 OT DMZ (VLAN 30) | Historian, HMI | 2 | Shared with IT/remote users; must not be a pivot into OT |
| Z4 Remote access (VPN) | Engineer, viewer | 2 | Authenticated, role-separated |
| External | Uplink / corporate / internet | - | Untrusted |

| Conduit | From -> to | Protocol | Controls |
|---|---|---|---|
| C1 | Z2 gateway -> Z1 devices | Modbus/TCP 502, ICMP echo | source IP + device set + port, SNAT, logged denies |
| C2 | Z2 gateway -> Z3 historian | HTTP 8086 | write-only token, source pinned |
| C3 | External / Z4 -> Z3 HMI | HTTP 3000 | DNAT of one port only, Grafana auth, no sign-up |
| C4 | Z4 engineer -> Z3 historian | HTTP 8086 | VPN peer identity, read token |
| C5 | Z4 engineer -> Z2 | SSH 22 | VPN peer identity + SSH keys |

## Foundational requirements (IEC 62443-3-3) - what is implemented

| FR | System requirement (examples) | Implementation in this lab | Gap / next step |
|---|---|---|---|
| FR1 Identification & authentication | SR 1.1 human users, SR 1.2 software processes, SR 1.5 authenticator mgmt, SR 1.7 password strength | SSH key-only (Ansible), Grafana admin with generated password, InfluxDB per-client tokens, WireGuard per-peer keys + PSK | No central IdP/LDAP; Modbus devices cannot authenticate (protocol limitation - compensated by C1) |
| FR2 Use control | SR 2.1 authorization enforcement, SR 2.8 auditable events | Role separation: gateway write-only, HMI read-only, viewer vs engineer VPN peers; auditd rules on config/firewall/secrets; Modbus writes logged by device (`sim.audit`) and gateway | Grafana roles per user; per-command authorization for setpoints |
| FR3 System integrity | SR 3.1 communication integrity, SR 3.4 software integrity | WireGuard (authenticated encryption) for remote access; pinned package versions; config baseline with hashes; read-only container filesystems | Modbus/TCP security (TLS, port 802) where devices support it; image signing |
| FR4 Data confidentiality | SR 4.1 information confidentiality | Secrets in `.env`/`/etc/bess-lab` mode 0600, not in git; tokens passed as files | TLS on HMI and historian inside the DMZ |
| FR5 Restricted data flow | SR 5.1 network segmentation, SR 5.2 zone boundary protection, SR 5.3 general-purpose person-to-person communication restrictions | 4 zones, default-deny forward policy, explicit conduits, no OT internet egress (masquerade disabled), SNAT so lower zones cannot route upward, anti-spoofing (fib rp-filter) | Unidirectional gateway for the historian at SL 3+; DPI for Modbus function codes |
| FR6 Timely response to events | SR 6.1 audit log accessibility, SR 6.2 continuous monitoring | Rate-limited NFLOG drop logging, persistent journald, alarm journal in the historian, comms/heartbeat supervision, drift check timer | Ship logs to a SIEM; IDS on the field VLAN |
| FR7 Resource availability | SR 7.3 control system backup, SR 7.4 recovery and reconstitution, SR 7.6 network and security configuration settings, SR 7.7 least functionality | Daily backup with checksums and retention, tested restore, configuration baseline + drift detection, idempotent Ansible rebuild, store-and-forward buffer, unused services disabled, dropped capabilities | Redundant gateway; UPS/host monitoring |

## Before vs after

`docker-compose.simple.yml` is the flat network many small sites start with: every host can reach
every other host on any port. `docker-compose.yml` is the segmented design. `lab/netns-lab.sh test`
demonstrates the difference with 20 automated checks (allowed conduits, denied flows, NAT, spoofing).

## Secure development lifecycle touches (IEC 62443-4-1 flavour)

- Configuration is code and reviewed in git (Ansible vars, register map, alarm list, dashboards).
- Generated artefacts (firewall policy, register-map doc, alarm list, dashboards) are produced from one
  source; `make check` fails if a committed artefact is out of date.
- Automated tests: codec vectors, alarm logic, end-to-end historian path, FAT runner, network policy.
